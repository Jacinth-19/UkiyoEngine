# Anime style library

50 starter shader graphs, every one built from the shader graph's own node library - no hand-written GLSL. The point is variety: an anime game is not one look. A face wants an SDF shadow that never breaks under the nose, hair wants an anisotropic ring, a uniform wants matte cloth with painted AO, a flashback wants 90s TV dither, a boss wants hard ink and no ambient at all.

Each style is a finished look *and* a starting point. Everything its look depends on is exposed as a material property with the default that makes the reference image, so a fine-tuned variant needs no graph editing: assign the shader, move the sliders.

Sources live in `tools/shader_graphs/Anime*.json`. `python3 tools/compile_shader_graphs.py compile tools/shader_graphs assets` - or `ukiyo_shader_tool compile tools/shader_graphs assets` with Qt - writes `assets/Shaders/Anime*.ukshader`, which the material inspector lists as soon as it exists. Both files are generated by `tools/gen_anime_styles.py`: edit the recipe, not the JSON or the shader.

## Using a starter

1. Assign `assets/Shaders/Anime<Family>_<Style>.ukshader` to a material, or open it in the shader graph editor to see how the look is wired.
2. Set properties in the material inspector. Unassigned texture slots sample white, so every style is usable before any art exists.
3. Duplicate the shader when a property is not enough, then rewire: the recipes are small on purpose (10-50 nodes) so a change stays readable.

## Conventions every recipe follows

* **Colour** comes from `albedo()`: a texture times a tint, so recolours and untextured props work with the same shader.
* **Light** comes from the scene: `Cel Bands` over N.L, then `Sun Color` and `Ambient Color` (hemisphere). A style that ignored the scene's lights would not sit in a level next to one that respects them.
* **Masters** are chosen for what they give back: `Toon` for the engine's own two-tone branch, `Unlit` when the style computes its whole look itself, `PBR` when it should still catch real specular and sky light.
* **Outlines** are the three exposed values `outlineColor`, `outlineWidth`, `outlineAlpha`, which ask the engine for the inverted-hull pass. Character styles expose them; ink, world and retro styles mostly do not.
* **Glow** means additive: into `Emission` on a lit master, straight into `Color` on `Unlit`. Rim lights, specular shapes and light sweeps are all built that way.

## Node coverage

The 50 styles exercise 63 of the 67 node types in `editor/src/shader_graph/sg_nodes.cpp`. They do not use `HeadForward`, `SubtractV3`, `ComplexLitMaster`, `BakedLitMaster`.

That gap is deliberate. `Complex Lit` and `Baked Lit` are for clear-coat paint and lightmapped statics, which the engine's own built-in shaders already cover; `Head Forward` is for hand-authored face rigs (`assets/Shaders/NahidaFace.ukshader` reads the same frame field); `Subtract V3` is a convenience next to `Add V3` with a negated operand. All four are still compiled and type checked by `tools/sg_coverage_check.py`, which builds one graph per node.

Checks that keep the library honest:

* `python3 tools/gen_anime_styles.py` - refuses to write a graph the code generator rejects, a style with no master, or a style that exposes nothing to tune.
* `Builder.wire()` in `tools/sg_build.py` - every connection is kind checked against the node table, the same check QtNodes makes in the editor, so a recipe cannot wire a float into a colour input.
* `python3 tools/compile_shader_graphs.py verify assets` - every shipped `.ukshader` is byte identical to a fresh compile of its own graph.
* `python3 tools/sg_glsl_check.py` - type checks the generated GLSL of every shipped shader.
* `python3 tools/sg_coverage_check.py` - compiles one graph per node type and reports which ones no shipped shader uses.
